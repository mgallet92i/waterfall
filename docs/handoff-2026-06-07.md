## Gotchas découverts (lire avant de reprendre l'implémentation)

- **Hook `wf-auth.sh` (PreToolUse Bash)** : (a) **bloque l'outil Write** pour les subagents (agent_type inconnu → default-block hors `wf/needs/`) → un subagent qui doit créer un fichier passe par un **heredoc Bash** vers une cible hors `wf/needs/`. (b) **bloque toute commande Bash contenant littéralement `--complete PHASE:STEP`** (il croit à un vrai appel et vérifie l'identité ; le main = `agent_type=pm`) → pour tester/exercer `--complete` sur des steps rv/or, passer par **bats** (sous-process non intercepté) ou un **sous-script** `bash x.sh`.
- **bats sur git-bash Windows = lent** : chaque test de state-machine spawn plusieurs `node` via `wf-orchestrate`. Pendant le dev, lancer **un fichier à la fois** ; éviter de relancer la full-suite en redondance.
- **Workflows : right-size.** Le 1er workflow (3 vérificateurs relançant chacun la full-suite bats) a pris ~2h45. Préférer **scouts read-only + 1 implémenteur + vérif bats faite inline** (par le main). Pour l'authoring de tests : 1 fichier par auteur, chacun ne lance que son fichier.
- **Helper de test** (`tests/wf-orchestrate-helper.bash`) : projet isolé git-init sous `BATS_TEST_TMPDIR` via `WF_PROJECT_ROOT`. **Limite connue** : `DV_IMPLEMENT` (artefact="") n'est pas testable en isolation (le helper git-init sans commit initial → `git diff HEAD` fatale exit 128) — cas omis explicitement dans `artifact-gate`.
- **Fixes de scripts** (`.sh`) : actifs au prochain appel (re-lus à chaque invocation) — pas de `/reload-plugins`. **Fixes de persona** (`.md`) : nécessitent `/reload-plugins` (HO) ET ne touchent jamais un agent déjà spawné → atterrissent entre needs.
- **CRLF** : le repo est en CRLF sous Windows ; pour comparer une extraction `awk`/`grep` du script à une sortie `jq`, strip le `\r` avec `tr -d '\r'` (pas via une regex `[\r]` dans awk, non interprétée ici).
