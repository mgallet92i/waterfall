# `.wf-config.json` — Schéma de configuration

Ce fichier documente le format attendu pour `.wf-config.json` à la racine du projet. Si le fichier est absent, les valeurs par défaut ci-dessous s'appliquent. Les valeurs sont validées au bootstrap (`scripts/wf-read-config.sh`) — toute valeur hors liste stoppe le workflow avec un message d'erreur.

## Exemple complet (valeurs par défaut)

```json
{
  "models": {
    "pm": "sonnet",
    "or": "sonnet",
    "po": "sonnet",
    "tl": "opus",
    "rv": "opus",
    "qa": "sonnet",
    "dv": "sonnet",
    "ds": "haiku"
  },
  "review_loops": {
    "artifacts": 2,
    "code": 3
  },
  "watchdog": {
    "interval": "5min"
  },
  "agent_mode": "team",
  "dark_factory": "off",
  "statusline": false
}
```

## Champs

### `models.<role>` — modèle Claude par rôle
Rôles : `pm`, `or`, `po`, `tl`, `rv`, `qa`, `dv`, `ds`
Valeurs acceptées : `opus`, `sonnet`, `haiku`

- **pm** : chef de projet (orchestration team, bootstrap)
- **or** : orchestrateur (state machine, dispatch des steps)
- **po** : product owner (PRD, specs, tf)
- **tl** : tech lead (tech.md, management pool DV, code review)
- **rv** : reviewer croisé (revue artefacts PO/TL/DS)
- **qa** : exécution du plan de tests fonctionnels
- **dv** : développeur (implémentation + tests unitaires)
- **ds** : designer UI (ui.md si `has_ui:true`)

### `review_loops.<type>` — nombre max de boucles de revue
Valeurs acceptées : entier ≥ 1

- **artifacts** : revues artefacts (PRD, specs, tech, ui)
- **code** : revues du code livré par DV

### `watchdog.interval` — intervalle du cron watchdog
Valeurs acceptées : `off`, `3min`, `5min`, `10min`

`off` désactive le watchdog. Le cron réveille PM pour détecter les agents STUCK.

### `agent_mode` — mécanisme de spawn des agents
Valeurs acceptées : `team`, `subagent`

- **team** (défaut) : Agent Teams via `TeamCreate` + `SendMessage` inter-agents
- **subagent** : spawn via `Agent` tool, pas de `SendMessage` inter-agents (watchdog inter-agents désactivé)

### `dark_factory` — mode autonomie
Valeurs acceptées : `on`, `off`

- **on** : autonomie maximale, les agents valident les checkpoints seuls, décisions loguées
- **off** (défaut) : les checkpoints sont escaladés au HO via `AskUserQuestion`

### `statusline` — statusline waterfall
Valeurs acceptées : `true`, `false` (booléen)

Activée via `bash scripts/wf-statusline-apply.sh on` (backup atomique du `statusLine.command` utilisateur). Désactivée via `bash scripts/wf-statusline-apply.sh off` (restore du backup). Ne pas éditer ce champ à la main — laisser le script le gérer.

## Édition

Éditer directement `.wf-config.json`. Les valeurs sont relues à chaque `/waterfall:new` et `/waterfall:resume`. Un récap de la config résolue est affiché au bootstrap.
